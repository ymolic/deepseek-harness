# Agent Note: 持久完整移动客户端

Status: implemented

[English](2026-10-15-persistent-full-mobile-client.md) | 中文

## 问题

独立手机文本界面遗漏应用能力，并重复实现菜单、渲染和恢复行为。会话选择与短期授权使手机无法作为长期操作者客户端使用。Desktop 配对后仍显示二维码，使关闭弹窗看起来不安全。

## 决策

明确的整实例授权允许通过加密出站传输使用现有 Web 客户端。Host 分派已注册应用 handler 和 Gateway 流，而不是任意目标 URL。原有 Client 负责模型、权限、会话、附件和交互；传输不再实现第二套应用操作。这取代[会话范围手机控制](2026-10-15-session-scoped-mobile-control.zh.md)的默认范围，旧投影和有界回执的理由仍适用于兼容路径。

凭据服务拥有带版本的设备记录。中继持久保存认证摘要和房间元数据，不保存流量密钥或载荷。Host 卸载只断开连接，不撤销授权。手动忘记设备在持久撤销与网络删除前先拒绝本机工作；未确认删除保持可见，重启后也不能静默恢复为新权限。

配对使用短期一次性票据。已配对权限没有应用 TTL。浏览器保存不可导出的根密钥和 HttpOnly cookie；浏览器淘汰或 cookie 策略仍可能要求重新配对。每次连接和端点替换时通过根密钥认证的新挑战派生流量密钥。分方向序号和请求 ID 拒绝同一代次内的重放；不确定变更明确失败，绝不自动重发。

配对页拥有密钥和受控同源应用文档。其 service worker 转发资产和原生 HTTP 请求，不保留密钥或私密响应缓存。分片确认与按需二进制传输约束在途数据。Worker 重启可重新找到所属页面，无需保存凭据。

仅桌面使用的账号实现与引导图片在检测到原生桥接后通过包内异步 chunk 加载；普通浏览器不下载该 chunk。下载在途分片数由部署配置，最多 32 个，中继缓冲上限覆盖加密后的在途数据。上传限制、分片大小、响应拉取与线上确认格式保持不变。这减少未使用的启动字节与确认等待，不削弱授权，也不缓存私密响应。

## 考虑过的替代方案

**扩展独立手机 UI**需要复制每项 Web 能力及其生命周期。复用已交付 Client 可保留有效应用交互并减少分歧。

**通用网络隧道**暴露与已授权实例无关的目标。分派到已注册路由、bundle、前端资产和类型化流，保留应用校验。

**永不过期的配对链接**会把复制的 URL 变成永久登录材料。短期一次性配对与持久设备身份把扫码和长期信任分开。

**重连后重放待确认变更**可能重复执行已成功但丢失确认的操作。改为重新打开读取流，并保留应用原有回执语义。

**缓存私密响应以加快启动**增加权限隔离与失效管理义务。移除未使用的 Desktop 资源并扩大有界下载窗口，可处理已测得的传输成本，无需保留应用数据。

## 影响

整实例授权授予包括敏感配置和工具审批在内的操作者权限，不将 Session 改成完全访问执行模式。原生桌面集成仍限桌面；现有 browse 目录选择器服务远端目录选择。即使载荷加密，分发者和两端设备仍须可信。

Loader 测试覆盖整实例配对、已注册 RPC 和流、卸载保留与明确撤销。浏览器验收使用可部署中继和录制 Session。Chromium 模拟不能证明 iPhone Safari、蜂窝网络或长期后台验收通过。
