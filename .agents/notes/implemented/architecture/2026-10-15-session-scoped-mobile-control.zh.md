# Agent Note: 限定 Session 的手机控制

Status: implemented

[English](2026-10-15-session-scoped-mobile-control.md) | 中文

## 问题

手机需要跨网络与桌面明确选定的 Session（会话）交换文本。已有的认证 Client 具备广泛操作者权限，转发其通用 Remote 调用会授予超过选定 Session 的访问能力。传输中断还会让成功发送和确认丢失难以区分。

## 决策

[手机控制器](../../../../packages/api/mobile-controller/README.zh.md) 拥有针对同一个 agent（智能体）实例的短期授权。手机仅收到有界的用户与助手文本，可以发送文本或查询状态和回执。执行权限仍属于现有 agent、权限服务和持久化 Session 接收机制；手机不能改变授权的 Session、路径、权限或方法集合。审批与问题仍留在桌面。

单独配置的桌面凭据用于创建中继房间。一次性二维码 fragment 携带临时配对材料和加密秘密；中继不会收到该秘密。按方向派生的 HKDF 密钥及认证 AES-GCM 封装使被动中继操作者无法读取对话载荷。页面分发者和端点仍必须可信，因此不声称能够防护中继操作者替换下发的 JavaScript。

Host 在完整授权周期内保留请求 ID 和接收结果，不会淘汰回执后重新执行旧 ID。不确定结果保持不确定。重连使用新的认证浏览器通道及有界替换快照，不重放通用 RPC 流量。Stop 同步拒绝接收、清理本机资源，并报告中继是否确认撤销；之后再次明确 Stop 会重试未确认的撤销。Start 在撤销确认前不替换此类授权。

## 考虑过的替代方案

**转发通用操作者 RPC** 能复用已有 Client 传输，但会开放超出手机同意范围的工作区、文件系统和管理方法。受限执行器使授权范围可以独立于手机 UI 强制落实。

**仅使用 TLS** 能保护网络链路，但允许中继读取聊天内容。载荷加密提供更窄但有用的保证，同时明确保留对下发页面的信任要求。

**自动重试发送或淘汰回执** 可能在确认丢失后重复执行消息。查询回执，并且只在收到未见结果后由用户明确以相同 ID 重试，可以保留原接收决定。有界授权和回执数量使这些状态保持有限。

**通用分片 RPC 重放** 为手机不会使用的操作增加重组、保留和背压职责。有界完整文本快照足以恢复所需视图；大规模历史和任意二进制载荷被明确排除。

## 后果

实际 Loader 组合检查真实 agent 接收、录制回复、重复 ID、撤销重试和插件释放。浏览器检查覆盖同意授权和二维码生命周期。单元检查拒绝越权字段、伪造封装、序号缺口、重放和过时发布。部署验收仍需要兼容中继；Chromium 手机模拟不能证明 iPhone Safari 行为或网络可靠性。

授权在十分钟内过期，不能跨 Host 重启保留，只支持一个 Session。断线桌面不能接收手机命令。网络分区可能阻止确认中继删除，但不能使本机已撤销的 agent 接收其他请求。这些限制属于 DSH 自身设计，不是对参考应用服务器行为的断言。
